# School website and management system — Phase 1

A reusable Next.js + Supabase system that serves a public school website, an admin dashboard, and parent and student portals. All school-specific content comes from one file: `config/school.config.ts`.

## What's included in Phase 1

- **Public website**: home, about, academics, admissions (online application and status check), student life, news, events, gallery, staff directory, careers, result checker (scratch-card PIN), contact.
- **Auth and RBAC**: Supabase email and password sign-in, run on the server with generic error messages. A forced password change on first login, password reset, and role-based routing (staff → `/admin`, parent → `/parent`, student → `/student`) enforced in `proxy.ts` and again in each layout.
- **Database**: 48 tables for academics, results, finance, payroll, CMS and audit. Row-level security is on every table, and permissions are checked through `has_permission()`. Receipt and invoice numbers are generated by triggers. Published results and locked terms can't be changed. Every change to a sensitive table is written to the audit log.
- **Admin shell**: a sidebar that only shows the modules the user's role allows, a dashboard with live figures, and permission-gated placeholder pages for the Phase 2 modules.

## Reusing it for a new school

1. Edit `config/school.config.ts`. This sets the name, motto, contacts, colours, classes, subjects, fees, grading and page content.
2. Replace the images in `public/images/` (logo, hero, principal and gallery).
3. Connect a fresh Supabase project and set these environment variables: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` and `POSTGRES_URL_NON_POOLING`.
4. Run `pnpm db:setup`. It applies the migrations and syncs the config into the settings, classes and subjects tables. Use `pnpm db:seed` instead if you also want the demo data.
5. Create the first Super Admin:
   ```
   pnpm user:create --email head@school.ng --password 'Strong!Pass1' --role super_admin --name "Head Teacher" --force-change
   ```
6. Deploy to Vercel. Add your production URL to Supabase Auth's redirect URLs so password-reset emails work.

## Layout

```
config/school.config.ts   school identity and content
db/migrations/            schema, functions and triggers, RLS
db/seed/                  core roles and permissions, demo school
scripts/                  db-setup, create-user
app/(site)/               public website
app/admin/                staff dashboard
app/parent, app/student   portals
proxy.ts                  session refresh and role routing
```

Money is stored in kobo (bigint). The service-role key is only used by the CLI scripts and is never sent to the browser.
